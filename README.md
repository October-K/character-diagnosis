# キャラ診断 設定反映版

## 現在のGitHubサイトを更新する

1. ZIPを解凍します。
2. GitHubの `character-diagnosis` リポジトリを開きます。
3. **いちばん上の階層の `index.html` を、このZIPの `index.html` に差し替えます。**
4. 変更をコミットし、GitHub Pagesの更新が終わったらサイトを再読み込みします。

フォルダーやZIPごとではなく、中の `index.html` を、現在の同名ファイルと同じ場所にアップロードしてください。ダウンロード時に名前が変わった場合も、ファイル名を `index.html` にします。現在の `login.html` が同じ階層にあれば、既存のログインからそのまま進めます。

画像・CSS・JavaScriptはすべてHTMLに埋め込まれています。新しい画像フォルダー、外部ライブラリー、ビルド作業は必要ありません。

回答の戻る・見直し・やり直し、結果コピー、同率切り替え、ログアウトは引き続き利用できます。回答はページ内でのみ保持し、再読み込みで最初からになります。

## ログイン画面も新デザインにする場合

通常の更新では `optional-login.html` は使用しません。

1. 現在のGitHub上の `login.html` のパスワード設定行 `const PASSWORD = ...;` を確認します。
2. `optional-login.html` の同じ設定行を、現在使用している値に合わせます。以前のログイン用ZIPの値を引き継いでいるため、その後変更している場合は合わせてください。
3. **`login.html` に名前を変更**して、リポジトリ最上位へアップロードします。

既存と同じキー `characterDiagnosisAuth`、値 `ok` を使います。HTML内でパスワードを比較する簡易ログインであり、サーバーでファイルへのアクセスを制限する認証ではありません。

新しい空のリポジトリで使う場合は、パスワードを確認した `login.html` と `index.html` の2つを最上位に置きます。

## 確認した範囲

JavaScriptの構文、判定の計算、10人全員への到達、回答の戻る・進む・見直し・リセット、同率切り替え、コピーの代替手段、既存ログインキーとの連携を確認しました。20万組の回答サンプルを使い、各キャラが単独結果に出る具体例について、JavaScriptと独立した計算の一致を確認しています。

直接の衝突を選んだ場合の候補除外と、その回答を選び直した場合の解除も確認済みです。

ブラウザーの実画面確認や、公開中のGitHubサイトへの反映は行っていません。今回の変更は配布ファイル内にあります。
